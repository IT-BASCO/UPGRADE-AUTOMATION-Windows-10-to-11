# Contributing Guidelines

Thank you for your interest in contributing to this project! Your contributions help improve this tool for the entire IT community.

## How to Contribute

If you have suggestions for improvements or bug fixes, please follow these steps:

### 1. Bug Reports
Before opening a new issue, please ensure the following:
* Search the existing issues to ensure the bug has not already been reported.
* Provide sufficient details, including: Operating System version, PowerShell/Python version, and any relevant error logs.

### 2. Feature Requests
If you have a new feature idea:
* Open an issue with the `enhancement` label and describe your proposal.
* Wait for team feedback to ensure it aligns with the project roadmap and avoids duplicate efforts.

### 3. Pull Requests
To submit code, please follow this workflow:
1. **Fork** the repository.
2. Create a new branch with a descriptive name (e.g., `feature/add-log-rotation` or `fix/memory-leak`).
3. Apply your changes and ensure they align with the project structure (e.g., `src/` and `tests/`).
4. **Testing:** Before submitting, verify your code by running the existing tests located in the `tests/` directory.
5. Open a **Pull Request** targeting the `main` branch.

## Coding Standards
* **Python:** Follow `PEP 8` standards (using `black` and `flake8` for formatting is mandatory).
* **Scripts (PowerShell/Bash):** Please comment your code and use descriptive variable names.
* **Documentation:** If you add a new feature, ensure you also update the relevant section in `README.md` or `docs/`.

## Review Process
All Pull Requests are reviewed by the maintainers. If your changes require adjustments, you will receive feedback in the `Review` section. Once approved, your changes will be merged into the main branch.
